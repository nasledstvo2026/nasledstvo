## Архитектурное решение

Правило «дополняй, не перезаписывай» вынесено из промпта (который дрейфует) в код:

```
katya-raw.json  ──search-agent──▶  katya-verified.json  ──verify-agent──▶  katya_merge.py
                                        (окно прогона)                          │
                                                                                ├─▶ katya-data.json        (накопительная база, append-only)
                                                                                ├─▶ katya-summary-7d.json  (окно 7 дней + агрегаты всей базы)
                                                                                └─▶ katya-extra-seen.json  (seen-лист для дедупа поиска)
```

Гарантии скрипта:

- **append-only** — старые записи не удаляются никогда;
- **дедуп** по нормализованному URL (без `www`, хвостового `/`, `utm_*`, фрагмента);
- **бэкап** базы перед каждой записью + ротация (последние 30);
- **атомарная запись** (tmp + `os.replace`), права файла сохраняются (664);
- **guard**: если после merge записей стало бы меньше — запись отменяется (exit 3);
- битый JSON базы → отказ без перезаписи (exit 4);
- битый/пустой `katya-verified.json` → база не страдает;
- окно «7 дней» живёт только в `katya-summary-7d.json`, в базе его нет;
- `rejected` в базу не попадают, но попадают в seen-лист;
- канонизация названий банков (Сбер/Сбербанк/ПАО Сбербанк → Сбербанк) и источников (2GIS/2ГИС → 2gis.ru);
- **идемпотентность** — повторный прогон ничего не добавляет, поэтому скрипт вызывается
  дважды за сутки (verify-agent 07:55 и stats-agent 08:20 как страховка).
