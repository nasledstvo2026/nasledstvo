## 1. Цель

Создать на Фениксе агента «Социальный консультант» для консультирования по вопросам соцподдержки в РФ (инвалидность, ВБД, СВО, выплаты, льготы, региональные меры).

## 2. Целевая аудитория

- **Ирина** — Telegram ID: `{УТОЧНИТЬ У КИРИЛЛА}`
- Чат: прямой (direct), существующий канал с Фениксом
- Новый канал/бот не создавать

## 3. Архитектура (на основе 425-ФЗ, без RAG)

### Зона 1 — Request Flow

```
Ирина (Telegram) → Gateway Феникса → main (курьер)
  → распознавание отправителя (sender ID Ирины)
  → sessions_spawn("social-consult-agent", isolated, stateless)
  → social-consult-agent формирует ответ
  → sessions_send("social-verify-agent") для проверки фактов
  → верифицированный ответ → Ирине
```

**Ключевые свойства:**
- Stateless isolation: каждый запрос — sessions_spawn с cleanup=delete (как у fz425-agent)
- Накопление контекста исключено
- main НЕ консультирует — только маршрутизирует

### Зона 2 — Knowledge Base

База знаний в файлах на Фениксе: `/home/user1/phoenix/social-consult-agent/knowledge/`

```
knowledge/
├── federal-law.md       # Федеральные законы (181-ФЗ, 5-ФЗ и др.)
├── payments-table.md    # Таблицы выплат (ЕДВ, НСУ, региональные)
├── categories.md        # Категории граждан и их права
├── svo-decrees.md       # Указы и НПА по СВО
├── moscow-region.md     # Региональные меры (Москва)
├── terms.md             # Глоссарий (ЕДВ, НСУ, ВБД, СВО, МСЭ и др.)
├── social-npa-db.json   # Структурированная БД проверенных фактов (автообновление)
└── weekly-update.md     # Лог изменений законодательства
```

### Зона 3 — Поиск (вместо RAG)

**Трёхуровневая модель поиска:**

1. **Категоризация** (social-category-matcher)
   - Определение категории: инвалидность / ВБД / СВО / не тема
   - Маршрутизация на конкретные файлы БЗ

2. **Файловый поиск** (чтение релевантных .md-файлов)
   - По результатам категоризации — чтение нужных файлов
   - Для кросс-категорийных вопросов — чтение нескольких файлов

3. **Web-поиск** (fallback)
   - Если в БЗ нет ответа — web_search по garant.ru, consultant.ru, sfr.gov.ru
   - Результаты верифицируются перед включением в ответ

### Зона 4 — Инфраструктура

- safe-restart.sh для перезапуска гейтвея Феникса
- sessions_spawn isolated для каждого запроса
- Отдельный workspace для social-consult-agent

## 4. Компоненты

### 4.1 social-consult-agent (основной агент)

**Роль:** Эксперт по социальной поддержке в РФ

**Workspace:** `/home/user1/phoenix/social-consult-agent/`

**Обязанности:**
1. Принимать вопрос от Ирины (через sessions_spawn от main)
2. Категоризировать вопрос через social-category-matcher
3. Читать релевантные файлы БЗ
4. Формировать черновик ответа со ссылками на НПА
5. Отправлять факты на верификацию в social-verify-agent
6. После вердикта — отправлять ответ Ирине

**Правила:**
- Каждый ответ содержит ссылки на конкретные статьи НПА
- Суммы выплат — с указанием даты актуальности
- Если точных данных нет — «требует уточнения», не додумывать
- Не консультировать по темам вне соцподдержки

**Конфигурация агента:**
```json
{
  "id": "social-consult-agent",
  "description": "Социальный консультант: инвалидность, ВБД, СВО, выплаты, льготы",
  "workspace": "/home/user1/phoenix/social-consult-agent/",
  "model": {
    "primary": "deepseek/deepseek-v4-pro",
    "fallbacks": ["deepseek/deepseek-v4-flash"]
  },
  "subagents": {
    "allowAgents": ["social-verify-agent"]
  }
}
```

### 4.2 social-verify-agent (верификатор)

**Роль:** Верификатор юридических фактов по соцподдержке

**Workspace:** `/home/user1/phoenix/` (общий с fz425-verifier)

**Обязанности:**
1. Принимать факты от social-consult-agent через sessions_send
2. Проверять каждый факт по приоритету источников:
   - garant.ru → docs.cntd.ru → consultant.ru → sfr.gov.ru
3. Возвращать вердикт: ✅ / ❌ / 🔄 / ❓

**Протокол верификации:** social-verifier-protocol (перенести с Лунтика)

**Конфигурация агента:**
```json
{
  "id": "social-verify-agent",
  "description": "Верификатор НПА по соцподдержке",
  "workspace": "/home/user1/phoenix/",
  "model": {
    "primary": "deepseek/deepseek-v4-pro",
    "fallbacks": ["deepseek/deepseek-v4-flash"]
  },
  "tools": {
    "allow": ["web_search", "web_fetch", "sessions_send"]
  }
}
```

### 4.3 main (курьер)

**Изменения в main на Фениксе:**
- Добавить биндинг: `sender_id = {ID Ирины}` → sessions_spawn("social-consult-agent")

## 5. Порядок выполнения

### Этап 1. Подготовка (Феникс)
1. Создать workspace `/home/user1/phoenix/social-consult-agent/`
2. Скопировать с Лунтика скиллы:
   - `social-category-matcher` → в skills Феникса
   - `social-verifier-protocol` → в skills Феникса
3. Создать структуру knowledge/ с начальными файлами БЗ
4. Создать `SKILL.md` для social-consult-agent

### Этап 2. Конфигурация агентов (Феникс)
1. Добавить `social-consult-agent` в agents.list openclaw.json
2. Добавить `social-verify-agent` в agents.list openclaw.json
3. Обновить `main.subagents.allowAgents` — добавить social-consult-agent
4. Обновить `agentToAgent.allow` — добавить social-consult-agent и social-verify-agent
5. Обновить биндинги — добавить маршрутизацию Ирины

### Этап 3. Наполнение БЗ (Феникс)
1. Заполнить federal-law.md (181-ФЗ, 5-ФЗ — основные статьи)
2. Заполнить payments-table.md (актуальные размеры выплат на 2026)
3. Заполнить categories.md (категории граждан)
4. Заполнить svo-decrees.md (указы по СВО)
5. Заполнить terms.md (глоссарий)
6. Создать social-npa-db.json (пустой, для cron-обновлений)

### Этап 4. Тестирование (Феникс → Лунтик)
1. Тест 1: запрос «Какие выплаты положены инвалиду II группы?»
2. Тест 2: запрос «Льготы для ветерана боевых действий»
3. Тест 3: запрос «Выплаты семье мобилизованного»
4. Тест 4: запрос не по теме (отказ)
5. Тест 5: запрос на стыке категорий

### Этап 5. Приёмка (Лунтик)
- Проверка всех 5 тестов
- Проверка stateless isolation (2 последовательных запроса — чистый контекст)
- Проверка верификации (все факты с вердиктом)
- Отчёт Кириллу

## 6. Критерии приёмки

| Критерий | Целевое значение |
|----------|-----------------|
| Корректность категоризации | ≥ 4/5 тестов |
| Наличие ссылок на НПА в ответах | 100% |
| Верификация фактов перед ответом | 100% |
| Stateless isolation | Подтверждено (чистый контекст) |
| Вежливый отказ на нецелевые вопросы | Да |
| Время ответа | ≤ 30 сек |
